# 排序算法可视化教学与实验数据管理平台 — 数据库课程设计文档

## 1. 问题的描述（背景及意义）

在计算机专业教学中，排序算法是数据结构与算法的核心内容。传统教学方式以理论讲解和静态图示为主，学生难以直观感受算法执行过程中的数据变化和性能差异。同时，教师缺乏有效手段跟踪学生的实验记录和对比不同算法的实际运行效果。

本系统旨在构建一个**排序算法可视化教学与实验数据管理平台**，通过 WebSocket 实时推送排序步骤，以柱状图动画展示算法执行过程；并通过 MySQL 数据库持久化存储每次实验的教学数据和性能测试数据，利用触发器、视图、存储过程等数据库对象实现自动化统计，为教学管理和算法研究提供数据支撑。

## 2. 需求分析

### 2.1 需求概述

系统面向三类用户：学生（Student）、教师（Teacher）、管理员（Admin）。学生可运行排序实验、查看个人历史；教师可查看全部学生实验数据和统计报表；管理员额外拥有数据库备份权限。

### 2.2 功能需求

1. **用户管理**：支持三种角色注册与登录，角色权限分级控制。
2. **教学实验管理**：记录每次排序实验的摘要数据（算法、数据量、比较/交换次数、耗时）和步骤快照，支持历史查询与回放。
3. **性能测试管理**：记录多算法对比测试的批次和明细，支持按每元素耗时排名。
4. **统计汇总**：触发器自动维护各算法教学与性能维度的滚动平均值。
5. **数据库备份**：管理员可一键导出标准 SQL 备份文件并恢复。

| 联系             | 参与实体            | 类型 | 说明                         |
| ---------------- | ------------------- | :--: | ---------------------------- |
| 发起教学实验     | 用户 → 教学实验     | 1:N  | 一个用户可执行多次教学实验   |
| 发起性能测试     | 用户 → 性能批次     | 1:N  | 一个用户可执行多次性能测试   |
| 使用算法（教学） | 算法 → 教学实验     | 1:N  | 一个算法被多次教学实验使用   |

| 统计汇总         | 算法 → 算法统计     | 1:1  | 每个算法对应一条统计记录     |
| 包含步骤         | 教学实验 → 实验步骤 | 1:N  | 一个教学实验包含多个步骤快照 |
| 包含明细         | 性能批次 → 批次明细 | 1:N  | 一个性能批次包含多个算法结果 |

## 4. 逻辑结构设计

### 4.1 由系统 E-R 图转化而得到的关系模式

```
users(user_id, username, password_hash, role, email, created_at)
    PK: user_id (VARCHAR(32) UUID)
    候选码: username (UNIQUE)

algorithms(algo_id, algo_code, algo_name, category, time_complexity,
           space_complexity, is_stable, pseudocode, description, advantages)
    PK: algo_id (BIGINT AUTO_INCREMENT)
    候选码: algo_code, algo_name (均为 UNIQUE)

teaching_experiments(exp_id, user_id, algo_id, data_size, total_steps,
                     comparisons, swaps, time_micros, interval_ms,
                     status, started_at, finished_at)
    PK: exp_id (BIGINT AUTO_INCREMENT)
    FK: user_id → users(user_id) ON DELETE CASCADE
    FK: algo_id → algorithms(algo_id) ON DELETE RESTRICT

experiment_steps(step_id, exp_id, step_number, data_json, highlight_json, description)
    PK: step_id (BIGINT AUTO_INCREMENT)
    FK: exp_id → teaching_experiments(exp_id) ON DELETE CASCADE

performance_batches(batch_id, user_id, data_size, distribution, data_type, created_at)
    PK: batch_id (BIGINT AUTO_INCREMENT)
    FK: user_id → users(user_id) ON DELETE CASCADE

batch_details(detail_id, batch_id, algo_id, comparisons, swaps, time_micros, `rank`)
    PK: detail_id (BIGINT AUTO_INCREMENT)
    FK: batch_id → performance_batches(batch_id) ON DELETE CASCADE
    FK: algo_id → algorithms(algo_id) ON DELETE RESTRICT

algorithm_stats(stat_id, algo_id, total_experiments, avg_exp_comparisons,
                avg_exp_swaps, avg_exp_time_micros, total_batches,
                avg_batch_comparisons, avg_batch_swaps, avg_batch_time_micros, updated_at)
    PK: stat_id (BIGINT AUTO_INCREMENT)
    候选码: algo_id (UNIQUE)
    FK: algo_id → algorithms(algo_id) ON DELETE CASCADE
```

## 5. 物理结构设计

### 5.1 描述

- **存储引擎**：InnoDB（支持事务和外键约束）
- **字符集**：utf8mb4（完整支持中文和 Emoji）
- **排序规则**：utf8mb4_0900_ai_ci
- **主键策略**：users 表使用 VARCHAR(32) + MyBatis-Plus ASSIGN_UUID，其余表使用 BIGINT AUTO_INCREMENT
- **JSON 字段**：experiment_steps 的 data_json 和 highlight_json 使用 MySQL JSON 类型，支持 JSON 函数查询

## 6. 数据库实现

### 6.1 表

### 6.2 视图

**v_algorithm_ranking** — 算法综合排名

```sql
CREATE VIEW v_algorithm_ranking AS
SELECT
    a.algo_name, a.category, a.time_complexity, a.is_stable,
    COALESCE(s.total_experiments, 0) AS teaching_count,
    COALESCE(s.total_batches, 0)    AS perf_count,
    COALESCE(s.avg_exp_time_micros, 0)   AS teach_avg_time_us,
    COALESCE(s.avg_batch_time_micros, 0) AS perf_avg_time_us,
    COALESCE(ds.avg_data_size, 0)   AS perf_avg_data_size,
    ROUND(s.avg_batch_time_micros / ds.avg_data_size, 2) AS perf_time_per_element_us,
    RANK() OVER (ORDER BY s.avg_batch_time_micros / ds.avg_data_size) AS speed_rank
FROM algorithms a
LEFT JOIN algorithm_stats s ON a.algo_id = s.algo_id
LEFT JOIN (
    SELECT bd.algo_id, ROUND(AVG(pb.data_size), 0) AS avg_data_size
    FROM batch_details bd
    JOIN performance_batches pb ON bd.batch_id = pb.batch_id
    GROUP BY bd.algo_id
) ds ON a.algo_id = ds.algo_id;
```

**v_user_activity** — 用户活跃度

```sql
CREATE VIEW v_user_activity AS
SELECT u.user_id, u.username, u.role,
    COALESCE(te.exp_count, 0)  AS teaching_experiments,
    COALESCE(pb.batch_count, 0) AS performance_batches,
    GREATEST(COALESCE(te.last_exp, '1970-01-01'),
             COALESCE(pb.last_batch, '1970-01-01')) AS last_activity
FROM users u
LEFT JOIN (
    SELECT user_id, COUNT(*) AS exp_count, MAX(started_at) AS last_exp
    FROM teaching_experiments GROUP BY user_id
) te ON u.user_id = te.user_id
LEFT JOIN (
    SELECT user_id, COUNT(*) AS batch_count, MAX(created_at) AS last_batch
    FROM performance_batches GROUP BY user_id
) pb ON u.user_id = pb.user_id;
```

### 6.3 触发器设计

| 触发器                          | 触发时机                          | 功能                                        |
| ------------------------------- | --------------------------------- | ------------------------------------------- |
| `trg_after_experiment_insert`   | teaching_experiments 表 INSERT 后 | 自动更新 algorithm_stats 教学维度滚动平均值 |
| `trg_after_batch_detail_insert` | batch_details 表 INSERT 后        | 自动更新 algorithm_stats 性能维度滚动平均值 |

两触发器均使用 `INSERT ... ON DUPLICATE KEY UPDATE` 实现增量滚动平均：

```
新平均值 = (旧平均值 × (总数-1) + 新值) / 总数
```

### 6.4 存储过程设计

**sp_user_report(IN p_user_id VARCHAR(32))** — 用户综合实验报告

返回 3 个结果集：

1. **综合统计**：教学维度（总实验/完成/停止/均比较/均交换/均时）+ 性能维度（批次/明细/均时）
2. **最常用算法**：按教学使用次数排名 TOP 1
3. **算法明细**：每个算法的教学与性能指标对比，含 `perf_vs_teach_ratio` 比值

> 使用子查询分别聚合教学和性能数据，避免多表 JOIN 产生笛卡尔积导致统计数据偏差。
